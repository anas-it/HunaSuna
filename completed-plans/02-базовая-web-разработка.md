# Завершенный план: базовая web-разработка HunaSuna

## Назначение

Этот документ фиксирует, что уже было разработано в web-версии HunaSuna.

Этап можно считать завершенным как базовую реализацию web-каркаса и основных сценариев. Перед релизом остаются отдельные важные проверки и расхождения со спеками, они перечислены в конце документа.

## Что было сделано

### 1. Подготовили Next.js проект

Был создан проект на Next.js с TypeScript.

В проекте есть:

- `app` для страниц и маршрутов;
- `app/api` для API;
- `components` для интерфейса;
- `server` для серверной логики;
- `server/services` для бизнес-логики;
- `server/auth` для авторизации и сессий;
- `server/validators` для проверки входящих данных;
- `server/jobs` для фоновых задач;
- `server/logs` для технических логов;
- `lib` для общих помощников;
- `prisma` для схемы базы данных и миграций.

### 2. Подготовили базу данных

Была создана Prisma schema.

Добавлены модели:

- `User`;
- `UserSession`;
- `LoginAttempt`;
- `Contact`;
- `Record`;
- `PasswordRecoveryCode`;
- `SecurityLog`;
- `ArchivedRecord`.

Добавлены миграции:

- начальная миграция;
- миграция сессий авторизации;
- миграция WhatsApp-поля контакта;
- миграция восстановления через секретный вопрос;
- миграция оптимизационных индексов;
- миграция удаления SMS-подтверждения, `SmsCode` и `phoneVerified`.

Добавлены индексы для:

- активных записей пользователя;
- удаленных записей;
- истории контакта;
- поиска по номеру телефона;
- контактов пользователя;
- архивирования удаленных записей;
- очистки архива.

### 3. Реализовали авторизацию и сессии

Было сделано:

- регистрация по логину и паролю;
- хеширование пароля;
- вход;
- выход;
- сессии через `UserSession`;
- хранение сессии в httpOnly cookie;
- режим “запомнить меня”;
- ограничение неправильных попыток входа;
- логирование успешного входа;
- логирование неправильного входа;
- восстановление пароля через секретный вопрос.

### 4. Реализовали личный кабинет

Было сделано:

- получение профиля пользователя;
- изменение имени;
- изменение фамилии;
- изменение email;
- изменение мобильного номера;
- изменение пароля;
- проверка текущего пароля перед показом чувствительных данных;
- логирование изменения данных аккаунта.

Удаление аккаунта не добавлялось, потому что оно не входит в первую версию.

### 5. Реализовали контакты

Было сделано:

- список контактов;
- пагинация контактов;
- создание контакта;
- редактирование контакта;
- мягкое удаление контакта через `deletedAt`;
- просмотр контакта;
- история записей по контакту;
- отдельное поле WhatsApp;
- нормализация номера телефона;
- логирование создания, редактирования и удаления контакта.

Старые записи не меняются при изменении или удалении контакта, потому что запись хранит снимок данных отправителя и получателя.

### 6. Реализовали записи

Было сделано:

- список записей;
- пагинация записей;
- просмотр одной записи;
- создание записи;
- редактирование записи;
- выбор отправителя и получателя из контактов;
- ручной ввод отправителя и получателя;
- сохранение суммы как строки;
- сохранение курса как строки;
- сохранение валюты;
- сохранение часового пояса;
- снимок имени, фамилии и телефона отправителя;
- снимок имени, фамилии и телефона получателя;
- запрет редактирования удаленной записи;
- логирование создания, редактирования и удаления записи.

Проект сохраняет информацию о переводах, но не выполняет денежные операции.

### 7. Реализовали удаленные записи

Было сделано:

- удаление записи переводит ее в состояние удаленной;
- для удаленной записи сохраняется `deletedAt`;
- для восстановления сохраняется `restoreUntil`;
- удаленная запись отображается в разделе “Удаленные”;
- удаленную запись можно восстановить в течение 7 дней;
- после восстановления очищаются `deletedAt` и `restoreUntil`;
- восстановление логируется.

### 8. Реализовали архив и фоновые задачи

Было сделано:

- сервис архивирования удаленных записей после истечения срока восстановления;
- перенос данных записи в `ArchivedRecord`;
- выставление `archivedAt` у исходной записи;
- очистка архивных записей после срока хранения;
- batch-обработка архивирования;
- cron route для очистки удаленных и архивных записей;
- защита cron route через `CRON_SECRET`.

Архивные записи не показываются обычному пользователю.

### 9. Реализовали поиск

Был сделан поиск по:

- имени и фамилии отправителя;
- имени и фамилии получателя;
- телефону отправителя;
- телефону получателя;
- контакту через `contactId`;
- номеру телефона.

Фильтр по валюте не добавлялся, потому что он не входит в первую версию.

### 10. Реализовали API

Добавлены route handlers:

- `/api/auth`;
- `/api/auth/[...all]`;
- `/api/users/me`;
- `/api/settings`;
- `/api/contacts`;
- `/api/contacts/[id]`;
- `/api/records`;
- `/api/records/[id]`;
- `/api/deleted-records`;
- `/api/deleted-records/[id]/restore`;
- `/api/search`;
- `/api/cron/deleted-records`.

API использует сервисы из `server/services` и проверяет текущего пользователя через серверную авторизацию.

Также добавлены:

## Что важно проверить перед релизом

Есть расхождения со спеками, которые нельзя забыть:

- собственная session-cookie авторизация зафиксирована как решение первой версии;
- нужно выполнить `npm run lint` и `npm run build`;
- нужно вручную пройти основные сценарии первой версии.

Базовая web-разработка выполнена: проект имеет рабочую структуру, страницы, API, базу данных, сервисы, записи, контакты, поиск, удаленные записи, архив и технические логи.
