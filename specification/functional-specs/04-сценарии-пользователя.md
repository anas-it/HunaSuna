# Сценарии пользователя HunaSuna

## Назначение документа

Этот документ описывает основные действия пользователя на сайте HunaSuna: от регистрации до создания, поиска, редактирования и удаления записи.

## Сценарий 1: Регистрация
Цель: пользователь создает свой аккаунт на сайте.

Шаги:
1. Пользователь открывает сайт.
2. Нажимает “Регистрация”.
3. Вводит логин, пароль и данные восстановления.
4. При желании вводит email и мобильный номер.
5. Нажимает “Создать аккаунт”.
6. Сайт создает аккаунт и открывает личный кабинет.

Результат: пользователь зарегистрирован, у него есть личная база данных.

SMS-подтверждение мобильного номера в первой версии не используется.

## Сценарий 2: Вход в аккаунт
Цель: пользователь входит в свой аккаунт.

Шаги:
1. Пользователь открывает страницу входа.
2. Вводит логин и пароль.
3. Нажимает “Войти”.
4. Сайт проверяет данные.
5. Если данные верные, открывается личный кабинет.

Результат: пользователь видит только свои контакты, записи и историю.

## Сценарий 3: Восстановление пароля
Цель: пользователь восстанавливает доступ, если забыл пароль.

Шаги:
1. Пользователь нажимает “Забыли пароль?”.
2. Вводит логин.
3. Сайт показывает секретный вопрос, сохраненный для этого аккаунта.
4. Пользователь вводит секретный ответ.
5. Вводит новый пароль и подтверждение нового пароля.

Результат: пользователь может снова войти в аккаунт.

SMS-коды, email-коды и временные коды восстановления в первой версии не используются.

## Сценарий 4: Добавление контакта
Цель: пользователь добавляет человека в контакты.

Шаги:
1. Пользователь открывает раздел “Контакты”.
2. Нажимает “Добавить контакт”.
3. Вводит имя, фамилию и номер телефона.
4. Нажимает “Сохранить”.

Результат: контакт сохранен и доступен при создании записи.

## Сценарий 5: Просмотр, редактирование и удаление контакта
Цель: пользователь смотрит информацию по конкретному контакту и при необходимости меняет или удаляет его.

Шаги:
1. Пользователь открывает раздел “Контакты”.
2. Выбирает нужный контакт.
3. Сайт показывает имя, фамилию, номер телефона и историю записей, связанных с этим контактом.
4. Пользователь может нажать “Редактировать” и изменить данные контакта.
5. Пользователь может нажать “Удалить”, если контакт больше не нужен.
6. Перед удалением сайт просит подтвердить действие.

Результат: пользователь видит, сколько этот контакт передавал и сколько получал. Если контакт удален, он больше не отображается в списке контактов, но история старых записей не меняется.

## Сценарий 6: Создание записи
Цель: пользователь создает запись об учете информации о переводе.

Шаги:
1. Пользователь нажимает “Создать запись”.
2. Указывает, от кого получены деньги: выбирает контакт или пишет имя, фамилию и номер телефона вручную, если номер есть.
3. Указывает сумму.
4. Выбирает валюту.
5. Указывает курс.
6. Указывает, кому переданы деньги: выбирает контакт или пишет имя, фамилию и номер телефона вручную, если номер есть.
7. Нажимает “Сохранить”.
8. Сайт автоматически добавляет дату и время по IP-адресу пользователя.

Результат: новая запись сохранена и появляется в истории.

## Сценарий 7: Просмотр истории записей
Цель: пользователь смотрит все свои записи.

Шаги:
1. Пользователь открывает раздел “История”.
2. Сайт показывает список записей.
3. В каждой записи видны дата, время, от кого, кому, сумма, валюта и курс.
4. Пользователь может редактировать или удалить запись.
5. Можно сортировать по дате.

Результат: пользователь быстро видит всю историю своей работы.


## Сценарий 8: Поиск записи
Цель: пользователь быстро находит нужную запись.

Шаги:
1. Пользователь открывает историю записей.
2. Вводит в поиск контакт или номер телефона.
3. Сайт показывает подходящие записи.

Результат: пользователь находит нужную информацию без ручного просмотра всей истории.


## Сценарий 9: Редактирование записи
Цель: пользователь исправляет ошибку в записи.

Шаги:
1. Пользователь открывает нужную запись.
2. Нажимает “Редактировать”.
3. Меняет нужные данные.
4. Нажимает “Сохранить”.

Результат: запись обновлена.

## Сценарий 10: Удаление записи
Цель: пользователь удаляет ненужную запись.

Шаги:
1. Пользователь открывает нужную запись.
2. Нажимает “Удалить”.
3. Сайт просит подтвердить удаление.
4. Пользователь подтверждает действие.

Результат: запись перемещается в раздел “Удаленные”. Ее можно восстановить в течение 7 дней. Пока запись находится в разделе “Удаленные”, ее нельзя редактировать. Если пользователь не восстановит запись в течение 7 дней, она исчезает из пользовательского интерфейса окончательно, но остается в техническом архиве базы данных без пользовательского доступа.


## Сценарий 11: Восстановление удаленной записи
Цель: пользователь возвращает удаленную запись, если передумал.

Шаги:
1. Пользователь открывает раздел удаленных записей.
2. Выбирает запись, удаленную не больше 7 дней назад.
3. Нажимает “Восстановить”.

Результат: запись снова появляется в истории.

Если прошло больше 7 дней, запись уже исчезла из пользовательского интерфейса и восстановление пользователем недоступно.

## Сценарий 12: Личный кабинет и настройки

Цель: пользователь меняет свои данные аккаунта.

Шаги:
1. Пользователь открывает раздел “Настройки” или личный кабинет.
2. Пользователь выбирает, что хочет изменить: пароль, имя, фамилию, email или мобильный номер.
3. Пользователь вводит новые данные.
4. Сайт просит подтвердить важные изменения, если это нужно для безопасности.
5. Пользователь сохраняет изменения.

Результат: данные аккаунта обновлены.

## Сценарий 13: Выход из аккаунта
Цель: пользователь безопасно завершает работу.

Шаги:
1. Пользователь нажимает “Выйти”.
2. Сайт завершает сессию.
3. Пользователь возвращается на страницу входа.

Результат: доступ к аккаунту закрыт до следующего входа.

## Общие правила сценариев
Все действия пользователя должны быть простыми и понятными.

Пользователь видит только свои данные.

На сайте используется слово “запись”, а не “тикет”.

Сайт не выполняет реальные денежные переводы, не хранит деньги, не принимает платежи и не работает как кошелек или банк.

Все данные должны сохраняться в аккаунте пользователя, чтобы их можно было использовать в мобильном приложении.

Удаление аккаунта пользователя в первой версии не входит.
