# Интерфейс HunaSuna

## Назначение документа

Этот документ описывает требования к внешнему виду, удобству и поведению интерфейса HunaSuna.

## Общий стиль
Интерфейс HunaSuna должен быть простым, спокойным и рабочим. Сайт не должен выглядеть как банк, обменник или платежная система.

Основной стиль: чистый, понятный, без лишних цветов и декоративных элементов.

Страница приветствия или входа может быть с анимированным фоном и подходящей надписью: "Добро пожаловать. Сохрани свой труд надежно и никогда не теряй историю."

Текст должен быть достаточно крупным. Кнопки должны быть заметными и удобными для нажатия.

Главная цель интерфейса: пользователь должен быстро создать запись, найти старую запись или открыть контакт.

## Главный экран после входа
После входа пользователь сразу видит рабочий экран.

На главном экране должны быть:

- свой логин;
- кнопка “Создать запись”;
- быстрый поиск;
- список последних записей;
- переход в контакты;
- переход в историю;
- переход в удаленные записи.


Главный экран не должен быть рекламной страницей. Это должен быть рабочий инструмент.

## Навигация
Навигация должна быть простой:

- Главная;
- Записи;
- Контакты;
- Удаленные;
- Настройки;
- Выйти.

Пользователь должен понимать, где он находится и как вернуться назад.

## Личный кабинет и настройки

В личном кабинете пользователь должен видеть свои основные данные аккаунта.

Пользователь должен иметь возможность изменить:

- пароль;
- имя;
- фамилию;
- email;
- мобильный номер.

Изменение данных должно быть простым и понятным. Для важных изменений сайт может просить подтверждение.

## Формы
Формы должны быть короткими и понятными.

В форме создания записи должны быть:

- от кого;
- сумма;
- валюта;
- курс;
- кому;
- кнопка “Сохранить”.

В полях “от кого” и “кому” пользователь может выбрать контакт или написать имя, фамилию и номер телефона вручную, если номер есть.

Номер телефона при ручном вводе не обязателен. Если номер не указан, поиск по номеру телефона такую запись не найдет.

Ошибки в форме должны показываться простым текстом.

## Контакты
Раздел контактов должен показывать список людей.

У контакта видно:

- имя;
- фамилия;
- номер телефона.

При открытии контакта пользователь видит простую историю всех записей, связанных с этим контактом.

История контакта должна показывать список записей с суммами: сколько этот контакт передавал и сколько получал.

Пользователь может редактировать или удалить контакт. Если контакт удален, он исчезает из списка контактов, но старые записи с этим контактом остаются в истории.


## Записи
На сайте используется слово “запись”, а не “тикет”.

Запись должна показывать:

- дату и время;
- от кого;
- кому;
- сумму;
- валюту;
- курс.

У каждой записи должны быть действия:

- открыть;
- редактировать;
- удалить.

## История записей
История должна быть удобной для просмотра.

Записи должны отображаться списком или таблицей. Пользователь должен быстро видеть главную информацию без лишних переходов.

Должна быть сортировка по дате.

## Поиск и фильтрация
Поиск должен работать по:

- контакту;
- номеру телефона.

Поиск должен быть заметным и доступным на экране истории.

Фильтрация может быть простой: по номеру телефона или контакту. Поиск и фильтр по дате в первой версии не делаем. Фильтрации по валюте в первой версии не должно быть.

## Удаленные записи
Удаленные записи должны быть в отдельном разделе.

Пользователь должен видеть, сколько дней осталось до окончательного исчезновения записи из пользовательского интерфейса.

Удаленную запись можно восстановить в течение 7 дней.

Пока запись находится в разделе “Удаленные”, ее нельзя редактировать. Чтобы изменить удаленную запись, пользователь сначала должен восстановить ее.

Если пользователь не восстановил запись в течение 7 дней, она исчезает из пользовательского интерфейса окончательно, но остается в техническом архиве базы данных без пользовательского доступа.

## Адаптация под мобильное приложение
Интерфейс сайта должен проектироваться так, чтобы его можно было удобно перенести в мобильное приложение.

Основные экраны должны быть простыми:

- главная;
- записи;
- контакты;
- создание записи;
- поиск;
- удаленные записи.

## Что нельзя делать в интерфейсе

Нельзя перегружать сайт лишними кнопками, цветами и сложными меню.

Нельзя использовать слова, которые создают ощущение платежной системы: кошелек, баланс, перевод средств, оплатить, карта.

Нельзя показывать сайт как банк или обменник.

Нельзя делать мелкий текст и маленькие кнопки.
