# Технические решения HunaSuna

## Назначение документа

Этот документ фиксирует основные технические решения для первой версии HunaSuna.

Цель документа - заранее выбрать технологии, чтобы разработка шла спокойно и без постоянной смены направления.

## Авторизация

Для первой версии использовать собственную session-cookie авторизацию.

Причина: текущая авторизация уже реализована в проекте, проще поддерживает вход по логину и паролю, хранит сессии в базе и не требует лишней внешней настройки для первой версии.

Использовать:

- таблицу `UserSession`;
- поле `loginNormalized` для входа и восстановления без учета регистра;
- httpOnly cookie для web-сессии;
- bearer session token для мобильного приложения через `Authorization: Bearer <token>`;
- хеширование session token в базе;
- `server/auth/session.ts` для создания, получения и удаления сессии;
- `server/auth/api.ts` для проверки API-запросов;
- `server/services/auth.service.ts` для регистрации, входа и восстановления доступа.

Better Auth не используется как обязательный механизм первой версии. Его можно рассмотреть позже, если появится реальная необходимость.

Мобильный номер можно хранить в аккаунте, но SMS-подтверждение в первой версии не используется.

Восстановление пароля в первой версии работает только через секретный вопрос и ответ. Email, SMS и временные коды восстановления не используются.

Мобильное приложение должно хранить session token только в защищенном хранилище устройства. Подробные правила описаны в `specification/mobile-specs/17-mobile-security.md`.

## База данных

Использовать PostgreSQL.

Для работы с базой использовать Prisma ORM.

Причина: Prisma удобно описывает таблицы, связи, миграции и хорошо подходит для Next.js.

## Среда базы данных

Для локальной разработки использовать PostgreSQL на компьютере разработчика.

Для будущего деплоя можно использовать Neon PostgreSQL.

Причина: локальная база удобна во время разработки, потому что проект работает без внешнего сервиса. Neon хорошо подходит для Next.js и Vercel, когда сайт будет опубликован.

## Интерфейс

Использовать Tailwind CSS и shadcn/ui.

Причина: HunaSuna нужен простой, чистый, рабочий интерфейс без лишних цветов. shadcn/ui дает готовые кнопки, формы, таблицы, модальные окна и элементы интерфейса.

## Хостинг сайта

Для первой версии использовать Vercel.

Причина: Vercel хорошо подходит для Next.js и поддерживает Route Handlers, переменные окружения и Cron Jobs.

## SMS

SMS-сервисы в первой версии не используются.

## Фоновые задачи

Использовать Vercel Cron Jobs.

Нужны задачи:

- каждый день проверять удаленные записи старше 7 дней;
- скрывать их из пользовательского интерфейса;
- переносить или копировать их в технический архив;
- оставлять архивные записи в техническом архиве базы данных без пользовательского доступа.

Cron endpoint должен быть защищен через секретный ключ `CRON_SECRET`.

## Проверка данных

Для проверки входящих данных использовать validators в `server/validators`.

Проверять:

- обязательные поля;
- доступ пользователя к своим данным;
- номер телефона;
- права на запись, контакт и удаленные записи.

## Итоговое решение

Первая web-версия HunaSuna строится на Next.js, PostgreSQL, Prisma ORM, собственной session-cookie авторизации, Tailwind CSS, shadcn/ui и Vercel. Мобильная версия строится как React Native/Expo/TypeScript приложение и использует тот же backend через API. Во время разработки база данных работает локально на компьютере, а для будущего деплоя можно использовать Neon PostgreSQL.
