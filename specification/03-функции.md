# Функции HunaSuna

## Назначение документа

Этот документ описывает функции первой версии HunaSuna. Здесь фиксируется, что обязательно нужно сделать в первой рабочей версии, что можно добавить позже, а что не входит в проект.

## Обязательные функции первой версии
Первая рабочая версия должна включать только основные функции, без которых продукт не сможет решать главную задачу пользователя.
Главная задача первой версии: дать пользователю возможность вести учет информации о переводах через сайт. Все данные должны храниться в аккаунте пользователя, чтобы в будущем эти же данные можно было использовать в мобильном приложении.

## Регистрация и вход
Пользователь должен иметь возможность зарегистрироваться на сайте и войти в свой аккаунт.

Регистрация:
- Логин
- Пароль
- Мобильный номер, если пользователь хочет добавить его сразу
- E-mail (если пользователь хочет)

После регистрации пользователь сразу может работать с аккаунтом. SMS-подтверждение мобильного номера в первой версии не используется.

Если пользователь забыл пароль, он может восстановить доступ через секретный вопрос и ответ. SMS-коды и email-коды восстановления в первой версии не используются.

У каждого пользователя должны быть свои данные: контакты, записи и история. Один пользователь не должен видеть данные другого пользователя.

Этот же аккаунт должен использоваться для входа в мобильное приложение.

В личном кабинете пользователь должен иметь возможность изменить пароль, имя, фамилию, email и мобильный номер.

## Контакты
Пользователь должен иметь возможность добавлять, редактировать и удалять контакты.

У контакта должны быть:

- имя;
- фамилия;
- номер телефона.

Контакты нужны для быстрого выбора человека при создании записи. При этом пользователь не обязан заранее добавлять контакт: при создании записи он может написать имя, фамилию и номер телефона вручную, если номер есть.

Открыв уже добавленный контакт, пользователь видит простую историю этого контакта: список записей, которые были с ним связаны, какие суммы он передавал и какие суммы получал.

Если пользователь удаляет контакт, контакт больше не отображается в списке контактов и его нельзя выбрать для новых записей. История старых записей не меняется: в ней остаются имя, фамилия и номер телефона, которые были сохранены на момент создания записи.

## Записи
Пользователь должен иметь возможность создавать запись об учете информации о переводе.

В записи должны быть:

- от кого получены деньги;
- кому переданы деньги;
- сумма;
- валюта;
- курс;
- дата и время создания записи.

В полях “от кого” и “кому” пользователь может выбрать уже добавленный контакт или написать имя, фамилию и номер телефона вручную, если номер есть.

Номер телефона при ручном вводе не обязателен. Если номер не указан, поиск по номеру телефона такую запись не найдет.

На сайте слово “тикет” не используется. Для пользователя это называется “запись”.


## Валюты и курс
Пользователь должен выбрать валюту операции.

В первой версии нужны валюты:

- турецкая лира;
- доллар;
- евро;
- рубль;
- китайский юань.

Пользователь должен вручную указать курс, по которому была сделана операция.

Пользователь может писать сумму и курс так, как считает нужным. В первой версии специальных ограничений по формату суммы и курса нет.

Автоматическое получение курса валют в первой версии не нужно.

## История записей
Пользователь должен видеть список всех своих записей.

В истории должны отображаться основные данные:

- дата и время;
- от кого;
- кому;
- сумма;
- валюта;
- курс.

История должна быть понятной и удобной для просмотра на компьютере и должна быть пригодна для мобильного приложения.


## Поиск и фильтрация
Пользователь должен иметь возможность быстро найти нужную запись.

Поиск должен работать по:

- контакту;
- номеру телефона.

Фильтрация может быть простой: по номеру телефона или контакту. Поиск и фильтр по дате в первой версии не делаем. Фильтрации по валюте в первой версии не должно быть.

## Редактирование и удаление
Пользователь должен иметь возможность редактировать запись, если он ошибся при вводе данных.

Пользователь должен иметь возможность удалить запись.

Желательно, чтобы перед удалением сайт спрашивал подтверждение.
Пользователь может восстановить удаленную запись в течение 7 дней, если он передумал после удаления.

После удаления запись переходит в раздел “Удаленные”. Пока запись находится в разделе “Удаленные”, ее нельзя редактировать. Сначала запись нужно восстановить, и только после этого ее можно снова редактировать.

Если пользователь не восстановил запись в течение 7 дней, запись исчезает из пользовательского интерфейса окончательно, но может храниться в архиве администрации 3 месяца.

## Что можно добавить позже
Позже можно добавить:

- расширение мобильного приложения;
- дополнительные мобильные сценарии после первого мобильного MVP;
- автоматическое получение курса валют;
- экспорт записей в Excel или PDF;
- расширенную аналитику;
- командную работу;
- роли сотрудников;
- резервное копирование из интерфейса;
- удаление аккаунта пользователя;
- уведомления;
- дополнительные валюты;
- загрузку документов или фото, если это будет нужно.


## Что не входит в первую версию
В первую версию не входят:

- мобильное приложение в составе первой web-версии;
- реальные денежные переводы;
- платежи;
- банковские карты;
- кошельки;
- хранение денег;
- комиссия;
- статус записи;
- автоматический курс валют;
- сложная аналитика;
- командные роли;
- чат между пользователями;
- удаление аккаунта пользователя.

## Критерии готовности функций
Функции первой версии считаются готовыми, когда пользователь может:

- зарегистрироваться;
- войти в аккаунт;
- открыть личный кабинет и изменить имя, фамилию, email, мобильный номер или пароль;
- добавить контакт;
- отредактировать или удалить контакт;
- создать запись;
- выбрать контакт или написать имя, фамилию и номер телефона вручную, если номер есть;
- указать сумму, валюту и курс;
- увидеть запись в истории;
- найти запись по контакту или номеру телефона;
- отредактировать запись;
- удалить запись;
- восстановить удаленную запись в течение 7 дней;
- выйти из аккаунта.

Также важно, чтобы все данные сохранялись в аккаунте пользователя и могли использоваться в мобильном приложении.
