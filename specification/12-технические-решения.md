# Технические решения HunaSuna

## Назначение документа

Этот документ фиксирует основные технические решения для первой версии HunaSuna.

Цель документа - заранее выбрать технологии, чтобы разработка шла спокойно и без постоянной смены направления.

## Авторизация

Для авторизации использовать Better Auth.

Причина: HunaSuna нужен вход по логину и паролю, подтверждение мобильного номера, восстановление доступа и подготовка к будущему мобильному приложению.

Использовать:

- Better Auth;
- username plugin для входа по логину;
- phone number plugin для подтверждения мобильного номера;
- Prisma adapter для хранения auth-данных в PostgreSQL.

Мобильный номер подтверждается SMS-кодом через Twilio Verify.

Если email добавлен и доступен для восстановления, он используется для восстановления пароля.

## База данных

Использовать PostgreSQL.

Для работы с базой использовать Prisma ORM.

Причина: Prisma удобно описывает таблицы, связи, миграции и хорошо подходит для Next.js.

## Среда базы данных

Для локальной разработки использовать PostgreSQL на компьютере разработчика.

Для будущего деплоя можно использовать Neon PostgreSQL.

Причина: локальная база удобна во время разработки, потому что проект работает без внешнего сервиса. Neon хорошо подходит для Next.js и Vercel, когда сайт будет опубликован.

## Интерфейс

Использовать Tailwind CSS и shadcn/ui.

Причина: HunaSuna нужен простой, чистый, рабочий интерфейс без лишних цветов. shadcn/ui дает готовые кнопки, формы, таблицы, модальные окна и элементы интерфейса.

## Хостинг сайта

Для первой версии использовать Vercel.

Причина: Vercel хорошо подходит для Next.js и поддерживает Route Handlers, переменные окружения и Cron Jobs.

## SMS

Основной SMS-сервис: Twilio Verify.

Запасной вариант: Vonage Verify.

SMS-код действует 5 минут.

Отправка SMS ограничена: не больше 3 SMS за 10 минут на один номер или IP.

## Фоновые задачи

Использовать Vercel Cron Jobs.

Нужны задачи:

- каждый день проверять удаленные записи старше 7 дней;
- скрывать их из пользовательского интерфейса;
- переносить или копировать их в технический архив;
- удалять архивные записи старше 3 месяцев.

Cron endpoint должен быть защищен через секретный ключ `CRON_SECRET`.

## Проверка данных

Для проверки входящих данных использовать validators в `server/validators`.

Проверять:

- обязательные поля;
- доступ пользователя к своим данным;
- номер телефона;
- SMS-коды;
- права на запись, контакт и удаленные записи.

## Итоговое решение

Первая версия HunaSuna строится на Next.js, PostgreSQL, Prisma ORM, Better Auth, Tailwind CSS, shadcn/ui, Twilio Verify и Vercel. Во время разработки база данных работает локально на компьютере, а для будущего деплоя можно использовать Neon PostgreSQL.
