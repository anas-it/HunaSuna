# Данные HunaSuna

## Назначение документа

Этот документ описывает, какие данные сайт должен хранить, как они связаны между собой и какие данные не должны храниться на сайте.

## Пользователь
У пользователя должны храниться:

- id пользователя;
- логин;
- нормализованный логин для входа и восстановления без учета регистра;
- пароль в защищенном виде;
- секретный вопрос;
- секретный ответ в защищенном виде;
- имя;
- фамилия;
- мобильный номер;
- email, если пользователь добавил;
- дата регистрации;
- дата последнего входа;
- дата изменения данных аккаунта.

Каждый пользователь видит только свои контакты, записи и историю.

Логин сохраняется в том виде, как его ввел пользователь, но для входа, восстановления доступа и проверки уникальности используется нормализованный логин в нижнем регистре. Например, `ADMINpro` и `adminpro` считаются одним логином.

Пользователь может менять пароль, имя, фамилию, email и мобильный номер в личном кабинете.

Пользователь может удалить только свой текущий аккаунт через личный кабинет. Для подтверждения удаления аккаунта сайт должен показать секретный вопрос пользователя и проверить введенный секретный ответ. Пользователь не может удалить аккаунт другого пользователя.

Восстановление пароля в первой версии работает только через секретный вопрос и ответ. Email и SMS для восстановления пароля не используются.

## Контакт
У контакта должны храниться:

- id контакта;
- id пользователя, которому принадлежит контакт;
- имя;
- фамилия;
- номер телефона;
- дата создания контакта;
- дата изменения контакта.

Контакт нужен, чтобы быстро выбирать человека при создании записи. При этом запись можно создать и без заранее добавленного контакта, если пользователь пишет имя, фамилию и номер телефона вручную, если номер есть.

Если пользователь удаляет контакт, контакт больше не отображается в списке контактов и его нельзя выбрать для новых записей. Старые записи не удаляются и не меняются.

## Запись
У записи должны храниться:

- id записи;
- id пользователя;
- от кого получены деньги;
- кому переданы деньги;
- сумма;
- валюта;
- курс;
- имя, фамилия и номер телефона отправителя на момент создания записи, если номер есть;
- имя, фамилия и номер телефона получателя на момент создания записи, если номер есть;
- часовой пояс записи, определенный по IP-адресу пользователя;
- дата и время создания записи;
- дата и время изменения записи;
- дата удаления, если запись удалена;
- дата, до которой запись можно восстановить.

Сумма и курс сохраняются в записи так, как их указал пользователь. В первой версии специальных ограничений по формату суммы и курса нет.

В полях "от кого" и "кому" пользователь может выбрать контакт или написать имя, фамилию и номер телефона вручную, если номер есть.

Если пользователь выбрал контакт, запись должна сохранить связь с этим контактом.

Если пользователь написал имя, фамилию и номер телефона вручную, запись должна сохранить эти данные как текст. Номер телефона при ручном вводе не обязателен.

Запись должна сохранять имя, фамилию и номер телефона контакта такими, какими они были на момент создания записи. Если контакт будет изменен или удален позже, старая запись не должна изменяться или удаляться вместе с контактом.

Для этого запись должна хранить не только связь с контактом, но и снимок данных на момент создания записи.

Для отправителя нужно хранить:

- id контакта отправителя, если был выбран контакт;
- имя отправителя на момент создания записи;
- фамилию отправителя на момент создания записи;
- номер телефона отправителя на момент создания записи, если номер есть.

Для получателя нужно хранить:

- id контакта получателя, если был выбран контакт;
- имя получателя на момент создания записи;
- фамилию получателя на момент создания записи;
- номер телефона получателя на момент создания записи, если номер есть.

Если контакт потом изменен или удален, эти сохраненные данные в записи не меняются.

## Валюта
В первой версии нужны валюты:

- турецкая лира;
- доллар;
- евро;
- рубль;
- китайский юань.

Валюта выбирается пользователем при создании записи.

## Курс
Курс указывается пользователем вручную.

Курс должен сохраняться в записи именно таким, каким его указал пользователь. Если курс изменится позже, старая запись не должна меняться.

В первой версии пользователь может написать курс в свободном формате без специальных ограничений.

## История контакта
История контакта формируется автоматически из записей, где этот контакт был выбран в поле "от кого" или "кому".

В истории контакта пользователь видит:

- дату и время;
- сумму;
- валюту;
- курс;
- был ли контакт отправителем или получателем.

Если имя, фамилия и номер телефона были введены вручную без выбора контакта, такая запись не привязывается к истории контакта, но должна находиться через поиск по номеру телефона, если номер был указан.

## Удаленные записи
Если пользователь удаляет запись, она не удаляется полностью сразу.

Запись попадает в удаленные и может быть восстановлена в течение 7 дней.

Пока запись находится в удаленных, ее нельзя редактировать. Для редактирования запись нужно сначала восстановить.

Для удаленной записи нужно хранить:

- дату удаления;
- дату, до которой можно восстановить запись.

Если пользователь не восстановил запись в течение 7 дней, запись исчезает из пользовательского интерфейса окончательно, но остается в техническом архиве базы данных без пользовательского доступа.

После исчезновения из пользовательского интерфейса запись больше не отображается пользователю и не может быть восстановлена пользователем через сайт.

При этом запись может оставаться в техническом архиве базы данных и резервных копиях, доступных только администрации сайта.

Архивная запись не должна быть доступна обычному пользователю, не должна отображаться в истории, поиске, контактах или разделе “Удаленные”.

Архивные записи остаются в техническом архиве базы данных без пользовательского доступа.

## Связи между данными
Один пользователь может иметь много контактов.

Один пользователь может иметь много записей.

Одна запись принадлежит только одному пользователю.

Один контакт может быть связан со многими записями.

Одна запись может быть связана с двумя контактами: "от кого" и "кому".

Запись может быть создана без связи с контактом, если пользователь написал имя, фамилию и номер телефона вручную.

## Правила хранения данных
Данные одного пользователя не должны быть доступны другому пользователю.

Пароль нельзя хранить обычным текстом.

Удаленные записи должны храниться 7 дней для восстановления.

После 7 дней удаленная запись исчезает из пользовательского интерфейса окончательно, но остается в техническом архиве базы данных без пользовательского доступа.

Поиск должен работать по контакту и номеру телефона. Поиск по дате в первой версии не делаем.

Данные должны храниться так, чтобы эти же аккаунты, контакты и записи можно было использовать в мобильном приложении.

Удаление аккаунта входит в первую web/mobile версию только как функция приватности и требование App Store. При удалении аккаунта из основной пользовательской базы должны удаляться аккаунт, сессии, контакты, записи, удаленные записи и архивные записи этого пользователя. Технические логи и резервные копии могут храниться ограниченное время для безопасности и обслуживания, но обычный пользователь не должен иметь к ним доступ после удаления аккаунта.

## Что не хранится на сайте
На сайте не хранятся:

- деньги;
- балансы;
- банковские карты;
- кошельки;
- платежные данные;
- реальные денежные переводы;
- комиссия;
- статус перевода;
- паспортные данные;
- документы, если эта функция не будет добавлена отдельно.
