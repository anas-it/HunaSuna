# Роли и доступ HunaSuna

## Назначение документа

Этот документ описывает роли пользователей и правила доступа к данным и функциям HunaSuna.

## Обычный пользователь
В первой версии HunaSuna есть одна основная роль: обычный пользователь.

Обычный пользователь может:

- зарегистрироваться;
- войти в аккаунт;
- открыть личный кабинет;
- изменить пароль, имя, фамилию, email и мобильный номер;
- добавлять контакты;
- смотреть свои контакты;
- смотреть историю контакта;
- создавать записи;
- смотреть свои записи;
- искать записи;
- редактировать свои записи;
- удалять свои записи;
- восстанавливать удаленные записи в течение 7 дней;
- удалить свой аккаунт после ответа на секретный вопрос;
- выйти из аккаунта.

## Владелец аккаунта
В первой версии обычный пользователь одновременно является владельцем своего аккаунта.

Владелец аккаунта имеет доступ только к своим данным:

- личный кабинет;
- контакты;
- записи;
- история;
- удаленные записи;
- настройки;
- удаление собственного аккаунта.

Владелец аккаунта не видит данные других пользователей, не видит пароли, не видит контакты других пользователей.

Пользователь не видит свой пароль или чужой пароль. Каждый пользователь может менять только свой пароль.

Каждый пользователь может удалить только свой текущий аккаунт, в котором он вошел. Для удаления аккаунта пользователь должен увидеть свой секретный вопрос и ввести секретный ответ. Удаление аккаунта входит в первую web/mobile версию только как функция приватности и требование App Store.

## Команда в будущем
В первой версии командная работа не нужна.

В будущем можно добавить команду, если пользователю нужно будет работать с сотрудниками.

В будущей версии могут появиться роли:

- владелец команды;
- помощник;

Но в первой версии эти роли не реализуются.

В будущей версии помощник сможет добавлять записи и редактировать только те записи, которые он сам добавил. Помощник не сможет удалять записи.

## Доступ к контактам
Пользователь видит только свои контакты.

Пользователь может:

- добавить контакт;
- открыть контакт;
- изменить контакт;
- удалить контакт;
- посмотреть историю контакта.

Контакты одного пользователя не должны быть доступны другому пользователю.

Если пользователь удаляет контакт, история записей не меняется и не удаляется вместе с контактом. В истории остаются имя, фамилия и номер телефона, которые были указаны в контакте на момент создания записи.

Удаленный контакт больше не отображается в списке контактов и не может быть выбран для новых записей.

## Доступ к записям
Пользователь видит только свои записи.

Пользователь может:

- создать запись;
- открыть запись;
- редактировать запись;
- удалить запись;
- восстановить удаленную запись в течение 7 дней.

Записи одного пользователя не должны быть доступны другому пользователю.

## Редактирование и удаление
Пользователь может редактировать только свои записи и контакты.

Перед удалением записи сайт должен просить подтверждение.

После удаления запись попадает в удаленные и может быть восстановлена в течение 7 дней.

Пока запись находится в разделе “Удаленные”, пользователь не может ее редактировать. Для редактирования запись нужно сначала восстановить.


## Восстановление удаленных записей
Пользователь может восстановить только свои удаленные записи.

Удаленная запись доступна для восстановления 7 дней.

Если пользователь не восстановил запись в течение 7 дней, она исчезает из пользовательского интерфейса окончательно, но остается в техническом архиве базы данных без пользовательского доступа.

## Администрация и технический архив
В первой версии нет отдельной роли администратора в пользовательском интерфейсе.

Доступ к архиву администрации должен быть только технический.

Обычный пользователь не видит архивные записи и не может их восстановить после 7 дней.

## Что пользователь не может делать
Пользователь не может:

- видеть данные других пользователей;
- редактировать чужие контакты;
- редактировать чужие записи;
- удалять чужие записи;
- восстанавливать чужие записи;
- делать реальные денежные переводы через сайт;
- хранить деньги на сайте;
- использовать сайт как кошелек, банк или обменник;
- заходить в чужой личный кабинет;
- восстанавливать чужие пароли;
- удалять чужие аккаунты.

Если пользователь не вошел в аккаунт, он не имеет доступа к личным кабинетам других пользователей.

Если пользователь пытается войти в чужой аккаунт и вводит неправильный пароль 5 раз, сайт должен временно запретить новые попытки входа с этого IP-адреса на 30 минут.

Ограничение входа должно учитывать не только IP-адрес, но и логин или мобильный номер, чтобы нельзя было бесконечно подбирать пароль к одному аккаунту с разных IP-адресов.
