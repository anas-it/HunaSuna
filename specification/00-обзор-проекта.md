# Обзор проекта HunaSuna

## Короткое описание
HunaSuna - это веб-инструмент для учета информации о переводах. Сайт помогает пользователю сохранять контакты, записи, суммы, валюты, курс, дату и историю. HunaSuna не переводит деньги и не хранит деньги, а только помогает удобно вести учет информации.

## Для кого проект
Проект создается для людей, которые занимаются учетом информации о переводах между клиентами и сейчас записывают данные в тетради, заметки, мессенджеры или разные файлы.

## Главная проблема
Пользователю сложно быстро найти старую информацию: когда была запись, какая была сумма, по какому курсу, от кого были получены деньги и кому они были переданы.

## Главное решение
HunaSuna дает пользователю личный аккаунт, контакты, записи, историю и поиск. Пользователь может быстро создать запись, выбрать контакт или ввести данные вручную, указать сумму, валюту и курс, а потом легко найти эту запись.

## Первая версия
В первую web-версию входят регистрация, вход, восстановление пароля через секретный вопрос и ответ, личный кабинет, контакты, записи, история, поиск, редактирование, удаление и восстановление записи в течение 7 дней.

## Не входит в первую версию
В первую web-версию не входят реальные денежные переводы, платежи, банковские карты, кошельки, хранение денег, комиссия, статус записи, командная работа, сложная аналитика, автоматический курс валют и удаление аккаунта. Мобильное приложение делается отдельной мобильной версией по активному плану.

## Главные правила продукта
HunaSuna должен оставаться инструментом учета информации. На сайте нельзя создавать функции, которые делают его похожим на банк, обменник, кошелек или платежную систему. На сайте используется слово “запись”, а не “тикет”.

## Главные данные
Сайт хранит пользователя, контакты, записи, сумму, валюту, курс, дату, время, номер телефона, email если указан, имя, фамилию, удаленные записи, архивные данные и технические логи безопасности.

## Безопасность
Каждый пользователь видит только свои данные. Мобильный номер можно хранить в аккаунте, но SMS-подтверждение в первой версии не используется. Пароли хранятся только в защищенном виде.

## Удаление и архив
Если пользователь удаляет запись, она переходит в раздел “Удаленные” на 7 дней. В этот период ее можно восстановить, но нельзя редактировать. Через 7 дней запись исчезает из пользовательского интерфейса окончательно, но может храниться в архиве администрации 3 месяца. Доступ к архиву только технический.

## Интерфейс
Интерфейс должен быть простым, спокойным и рабочим. Пользователь должен быстро создать запись, найти старую запись или открыть контакт. Не нужно лишних цветов, сложных меню и визуального ощущения банка или платежной системы.

## Техническая основа
Проект строится на Next.js. Backend первой версии делается через Route Handlers в `app/api`. Основная логика должна быть в `server/services`. База данных - PostgreSQL.

## Оптимизация
Списки записей, контактов, удаленных записей и истории контакта должны загружаться частями, а не целиком. API должен отдавать только нужные поля и возвращать данные пагинации. Подробные правила описаны в `specification/14-оптимизация.md`.

## Мобильное приложение
Мобильное приложение должно использовать те же аккаунты, контакты, записи, поиск, удаленные записи, API и правила безопасности. Подробные правила описаны в `specification/15-мобильное-приложение.md`, `specification/16-api-contract.md`, `specification/17-мобильная-безопасность.md` и активном плане `активные планы/01-мобильная-разработка.md`.

## Открытые вопросы
На данный момент основные решения первой версии зафиксированы. Открытые вопросы можно добавлять сюда, если во время разработки появятся новые спорные моменты.
