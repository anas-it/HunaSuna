# Безопасность HunaSuna

## Назначение документа

Этот документ описывает требования к безопасности, приватности и защите данных пользователей HunaSuna.

## Доступ к аккаунту
Пользователь входит в аккаунт по логину и паролю.

При регистрации мобильный номер обязателен. Email можно добавить по желанию.

При регистрации мобильный номер нужно подтвердить SMS-кодом на сайте.

Один пользователь не должен иметь доступ к данным другого пользователя.

После выхода из аккаунта доступ к данным должен закрываться до следующего входа.

Если пользователь вводит неправильный пароль 5 раз, сайт должен временно запретить новые попытки входа с этого IP-адреса на 30 минут.

Ограничение попыток входа должно учитывать не только IP-адрес, но и логин или мобильный номер, чтобы нельзя было бесконечно подбирать пароль к одному аккаунту с разных IP-адресов.

Пользователь не может заходить в чужой личный кабинет и не может восстанавливать чужие пароли.


## Пароли
Пароли нельзя хранить обычным текстом.

Пароль должен храниться только в защищенном виде.

Минимальная длина пароля - 4 символа.

Пользователь может выбирать любой пароль на свое усмотрение, если пароль не короче 4 символов.

## Мобильный номер и email
Мобильный номер используется для регистрации и восстановления доступа.

Email необязательный, но если пользователь его добавил, он может использоваться для восстановления пароля.

Мобильный номер и email должны быть видны только владельцу аккаунта.
Мобильный номер может быть любой страны мира и должен писаться с кодом страны.

SMS-код подтверждения мобильного номера при регистрации действует 5 минут.

Отправку SMS-кодов нужно ограничить: не больше 3 SMS за 10 минут на один номер или IP-адрес.

## Личный кабинет и настройки
В личном кабинете пользователь может менять свои данные аккаунта:

- пароль;
- имя;
- фамилия;
- email;
- мобильный номер.

Изменение пароля, email и мобильного номера должно быть защищено подтверждением, если это нужно для безопасности.

После изменения пароля старый пароль больше не должен работать.

## Восстановление пароля
Если пользователь забыл пароль, он может восстановить доступ через мобильный номер или email, если email подтвержден или был добавлен в личном кабинете.

Для восстановления через мобильный номер сайт отправляет SMS-код.

Для восстановления через email сайт отправляет код или ссылку, если восстановление через email доступно.

Код восстановления должен работать ограниченное время.

Код восстановления действует 5 минут.

Код восстановления можно ввести неправильно не больше 3 раз. После 3 неправильных попыток код должен стать недействительным.

После смены пароля старый пароль больше не должен работать.

## Доступ к данным пользователя
Каждый пользователь видит только свои данные:

- личный кабинет;
- свои контакты;
- свои записи;
- свою историю;
- свои удаленные записи.

Данные одного пользователя не должны быть доступны другому пользователю даже случайно.

## Защита личных данных
HunaSuna должен хранить только те данные, которые нужны для работы сайта.

Не нужно просить у пользователя лишнюю информацию.

Имя, фамилия, номер телефона, email, контакты и записи должны считаться личными данными.

Сайт должен быть построен так, чтобы в будущем можно было безопасно использовать эти же данные в мобильном приложении.

## Удаление и восстановление записей
Если пользователь удаляет запись, она не удаляется сразу полностью.

Удаленная запись переходит в раздел “Удаленные” и хранится там 7 дней, чтобы пользователь мог восстановить ее, если передумал.

Пользователь должен видеть, сколько дней осталось до окончательного исчезновения записи из пользовательского интерфейса.

Пока запись находится в разделе “Удаленные”, ее нельзя редактировать. Для редактирования запись нужно сначала восстановить.

Если пользователь не восстановил запись в течение 7 дней, запись исчезает из пользовательского интерфейса окончательно, но может храниться в архиве администрации 3 месяца.

После 7 дней запись больше не доступна пользователю и не может быть восстановлена пользователем через сайт.

При этом запись может оставаться в техническом архиве базы данных и резервных копиях администрации сайта.

Доступ к архивным записям должен быть строго ограничен администрацией сайта и не должен быть доступен обычным пользователям.

Срок хранения архивных записей администрацией - 3 месяца.

## Резервные копии
Данные должны регулярно сохраняться в резервных копиях.

Резервные копии нужны, чтобы не потерять данные при технической ошибке.

Доступ к резервным копиям должен быть ограничен.

Резервные копии могут содержать записи, которые уже окончательно удалены из пользовательского интерфейса. Доступ к таким данным должен быть только у администрации сайта.

## Логи и история действий
Сайт должен хранить техническую историю важных действий:

- вход в аккаунт;
- создание записи;
- редактирование записи;
- удаление записи;
- восстановление записи;
- смена пароля;
- изменение email;
- изменение мобильного номера.

Эта история нужна для безопасности и восстановления спорных ситуаций.

Пользователю не нужно показывать сложные технические логи, но в будущем можно добавить простую “Историю действий”.

## Что нельзя хранить
На сайте нельзя хранить:

- деньги;
- балансы;
- банковские карты;
- кошельки;
- платежные данные;
- паспортные данные;
- фото документов без отдельной необходимости;
- лишнюю личную информацию.

HunaSuna должен оставаться инструментом учета информации, а не платежной системой.
