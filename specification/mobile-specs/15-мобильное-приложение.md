# Мобильное приложение HunaSuna

## Назначение документа

Этот документ описывает первую мобильную версию HunaSuna.

Мобильное приложение - это отдельный клиент для того же продукта. Оно использует те же аккаунты, контакты, записи, удаленные записи, поиск, базу данных и backend, что и web-версия.

## Главная цель

Сделать мобильное приложение, где пользователь может вести учет информации о переводах с телефона без отдельного backend и без новых финансовых функций.

Приложение не переводит деньги, не хранит деньги, не показывает балансы, карты, кошельки, комиссии и не выглядит как банк, обменник, платежная система или сервис денежных переводов.

## Техническая основа

Для первой мобильной версии использовать:

- React Native;
- Expo;
- TypeScript;
- общий API web-проекта;
- `Authorization: Bearer <session token>` для мобильной авторизации;
- защищенное хранилище устройства для session token.

Мобильный проект хранится в папке `mobile`.

## Что входит в первый мобильный MVP

В первую мобильную версию входят:

- регистрация;
- вход;
- восстановление пароля через секретный вопрос и ответ;
- выход;
- главная после входа;
- контакты;
- просмотр контакта и истории записей по нему;
- создание, просмотр и редактирование записи;
- история записей;
- поиск по контакту и номеру телефона;
- удаленные записи;
- восстановление удаленной записи в течение 7 дней;
- настройки аккаунта.

## Что не входит в первый мобильный MVP

В первую мобильную версию не входят:

- реальные денежные переводы;
- платежи;
- банковские карты;
- кошельки;
- хранение денег;
- комиссия;
- статус записи;
- автоматический курс валют;
- поиск по дате;
- фильтр по валюте;
- offline-first синхронизация;
- отдельный backend для мобильного приложения;
- удаление аккаунта пользователя;
- командные роли;
- сложная аналитика.

## Основные экраны

## API и сессия

Мобильное приложение использует API из `app/api`.

После регистрации или входа мобильный клиент отправляет `client: "mobile"` или заголовок `x-hunasuna-client: mobile`. Backend возвращает session token и дату окончания сессии.

Все защищенные запросы мобильное приложение отправляет с заголовком:

```text
Authorization: Bearer <session token>
```

Web-версия продолжает использовать httpOnly cookie.

Подробный контракт API описан в `specification/technical-specs/16-api-contract.md`.

## Правила интерфейса

Интерфейс должен быть спокойным, рабочим и быстрым.

Использовать слово “запись”, а не “тикет”.

Не использовать слова и визуальные элементы, которые создают ощущение платежной системы: баланс, кошелек, карта, оплатить, комиссия, перевод средств.

Пользователь должен быстро:

- войти;
- создать запись;
- открыть контакт;
- найти запись;
- восстановить удаленную запись;
- изменить данные аккаунта.

## Критерии готовности

Мобильная версия считается готовой, когда пользователь может:

- зарегистрироваться;
- войти;
- восстановить пароль через секретный вопрос и ответ;
- добавить контакт;
- создать запись;
- найти запись по контакту или номеру телефона;
- отредактировать запись;
- удалить запись;
- восстановить запись в течение 7 дней;
- изменить основные данные аккаунта;
- выйти из аккаунта.

И при этом приложение использует общий backend, не раскрывает чужие данные и остается инструментом учета информации о переводах.
