# План мобильной разработки HunaSuna

## Статус

План активный.

Мы делаем мобильное приложение HunaSuna как отдельный клиент общего backend.

## Текущий прогресс

- 2026-06-04: мобильное приложение подключено к общему API web-версии для контактов, записей, поиска, удаленных записей и настроек аккаунта.
- Заглушка `Раздел в работе` заменена на рабочие мобильные экраны.
- Главный экран дополнен разделами `Удаленные` и `Настройки`.
- Заголовок `HunaSuna` на главном экране опущен ниже и оставлен текстом без отдельного логотипа.
- Главная навигация мобильного приложения переведена из списка кнопок в нижнюю панель: `Записи`, `Контакты`, `Создать запись`, `Удаленные`, `Настройки`; поиск вынесен в центр главного экрана.
- Нижняя навигация получила мягкие цветные иконки в современном мобильном стиле, а поиск на главном экране заменен на удобное поле ввода с быстрым переходом к результатам.
- Нижние иконки заменены на контурный стиль с прозрачным фоном; центральное действие `Создать запись` оформлено как прозрачная круглая кнопка с обводкой.
- Нижние иконки выровнены по одному уровню, `Создать запись` приведена к общему размеру, текст под иконками уменьшен, а реакция на нажатие перенесена только на иконку через легкую spring-анимацию.
- Главный экран обновлен: рядом с `HunaSuna` добавлена иконка, поиск поднят выше, кнопка-стрелка получила отдельную анимацию, под поиском выводится список записей.
- На главном экране мобильного приложения убрана надпись `HunaSuna`; сверху оставлен логин пользователя, а выход из аккаунта перенесен в мобильные настройки.
- Исправлен web-focus у мобильных полей ввода: стандартная оранжевая рамка Expo Web убрана, для поиска используется аккуратная рамка в стиле приложения.
- В мобильных разделах убраны поясняющие подписи под заголовками; форма создания/редактирования записи стала компактнее, выбор контакта перенесен в модальное окно с автозаполнением полей.
- Раздел `Контакты` в мобильном приложении переработан: форма стала компактнее, карточки контактов получили удобные действия, удаление вынесено в отдельную иконку без подписи.
- Раздел `Контакты` переведен на сценарий списка: сверху кнопка `Добавить`, список контактов остается основным экраном, а форма добавления или изменения открывается только по действию пользователя.
- В мобильном разделе `Контакты` карточки в списке теперь показывают только имя и фамилию, а телефон, WhatsApp и подробности контакта открываются в отдельном окне после удержания карточки.
- Карточки контактов в мобильном списке уплотнены до одной строки: имя и действия находятся на одном уровне, чтобы список не занимал лишнее место.
- Из компактных карточек контактов убраны буквенные аватары, чтобы длинные имя и фамилия помещались лучше и могли переноситься на две строки.
- В мобильный раздел `Контакты` добавлен живой поиск: список обновляется при вводе имени, фамилии или номера и показывает совпадения с начала значения.
- Раздел `Настройки` в мобильном приложении сделан компактнее: личный кабинет вынесен в карточку пользователя, блоки раскрываются по нажатию, лишние пояснения под заголовками убраны.
- На экран входа мобильного приложения добавлен адаптированный анимированный бренд-блок HunaSuna перед полями логина и пароля.
- Анимация бренд-блока HunaSuna на экране входа уточнена: буквы больше не масштабируются и остаются четкими, движение перенесено на подсветку и акцент.
- Бренд-блок HunaSuna на экране входа очищен от яркого внешнего свечения, а знак внутри переработан так, чтобы буквы читались яснее.
- Бренд-блок HunaSuna на экране входа обновлен под новый горизонтальный референс: знак, название и подпись `Smart Money Information` адаптированы под мобильный экран.
- Внутренняя часть знака HunaSuna упрощена и выровнена: буквы больше не накладываются друг на друга, логотип выглядит чище на мобильном экране.
- На экране входа установлен новый круглый логотип HunaSuna из предоставленного изображения; под логотипом оставлен текст `HunaSuna`, а визуальный эффект сделан мягким и не искажает знак.
- Логотип HunaSuna на экране входа перерисован в высоком качестве с `@2x` и `@3x` ассетами, а анимация приглушена, чтобы знак не мылся и не утомлял глаза.
- Надпись `HunaSuna` под логотипом на экране входа возвращена к прежнему стилю: `Huna` темным цветом, `Suna` бирюзовым.
- Экран входа адаптирован под открытую клавиатуру: логотип становится компактнее, контент поднимается, а поле пароля не закрывается клавиатурой.
- На экране входа убрана внешняя touch-обертка вокруг формы, чтобы поля логина и пароля на телефоне всегда получали фокус и открывали клавиатуру.
- Раздел `Записи` переработан под большой список: карточки стали компактнее, телефоны скрыты из списка, сумма выделена крупнее, поиск открывается по лупе, а подробности записи показываются в модальном окне после удержания карточки.
- В разделе `Записи` удержание карточки для подробностей сокращено до 1.5 секунды, добавлена сортировка по дате или алфавиту, список скрывается во время создания записи, а после сохранения новая запись открывается в списке с подсветкой.
- В мобильных формах записи и контакта убраны дублирующие подписи над полями, WhatsApp перенесен в placeholder, а список контактов скрывается под открытой формой контакта.
- Списки записей, поиска, удаленных записей и истории контакта в мобильном приложении переведены на пагинацию по 15 записей; сортировка выполняется на текущей выбранной странице.
- Мобильный поиск получил подсказки контактов по началу имени, фамилии и номеру, а модальное окно выбора контакта в форме записи получило собственный поиск.
- Поиск контактов в мобильных подсказках уточнен: имя, фамилия и номер ищутся по началу значения, чтобы цифра из середины номера не показывала лишние контакты.
- Общий поиск записей также переведен на совпадение с начала имени, фамилии или телефона, чтобы короткий ввод не показывал случайные совпадения из середины номера.
- В разделе `Записи` убраны контактные подсказки под полем поиска; поиск теперь показывает только записи и умеет находить их по паре имя+фамилия контакта.
- В разделе `Записи` контактные подсказки возвращены в аккуратном виде: показываются только реальные совпадения, а выбор контакта запускает поиск записей по `contactId`.
- Поиск записей по телефону нормализован: добавлены search-поля для телефонов в записи, чтобы поиск не зависел от пробелов и лишних символов.
- Mobile API client отправляет timezone, обрабатывает истекшую bearer-сессию автоматическим выходом и показывает понятные ошибки API-валидации.
- API больше не показывает пользователю внутренние Prisma-ошибки и stack trace; технические детали остаются только в логах сервера.
- CORS для Expo Web разрешает `X-HunaSuna-Timezone`, чтобы web-режим мобильного приложения мог входить и отправлять API-запросы из `localhost:8081`.
- CORS для Expo Web больше не зависит от одного LAN-IP, EAS config перенесен в `mobile/eas.json`, лишние описания под заголовками разделов убраны.

## Зафиксированные решения

- Мобильный проект хранится в папке `mobile`.
- Техническая основа: React Native, Expo, TypeScript.
- Для запуска через текущий Expo Go на телефоне используем Expo SDK 54.
- SDK 55/56 пока не используем в локальной мобильной разработке, если Expo Go на телефоне показывает поддержку только SDK 54.
- Expo organization slug: `hunasuna-smr`.
- Expo app slug: `hunasuna-mobile`.
- Expo/EAS project id: `e308951e-9dfb-4957-96ed-5d1c64c2e24c`.
- EAS build config хранится в `mobile/eas.json`, потому что Expo-проект находится в папке `mobile`.
- Backend общий с web-версией: Next.js Route Handlers в `app/api`.
- Отдельный backend для мобильного приложения не делаем.
- Web использует httpOnly cookie.
- Mobile использует тот же `UserSession`, но передает session token через `Authorization: Bearer <token>`.
- Session token хранится только в защищенном хранилище устройства.
- Восстановление пароля: только секретный вопрос и ответ.
- SMS-коды, email-коды и временные коды восстановления не делаем.
- Поиск: только по контакту и номеру телефона.
- Поиск по дате в первой мобильной версии не делаем.

## Этап 1: Создать мобильный проект

Нужно:

- создать папку `mobile`;
- настроить Expo + React Native + TypeScript;
- держать mobile-проект на Expo SDK 54, пока Expo Go на телефоне поддерживает SDK 54;
- создать/настроить приложение в Expo:
  - название организации: `HunaSuna`;
  - organizational slug: `hunasuna-smr`;
  - название приложения: `HunaSuna`;
  - app slug: `hunasuna-mobile`;
  - участников пока не приглашать, если команда не нужна;
- подключить локальный проект к Expo/EAS:
  - если CLI не вошел в Expo, сначала выполнить из папки `mobile`: `npx eas-cli@latest login`;
  - команда из папки `mobile`: `npx eas-cli@latest init --id e308951e-9dfb-4957-96ed-5d1c64c2e24c`;
  - project id также должен быть в `mobile/app.json` в `expo.extra.eas.projectId`;
  - на экране Expo “Создайте свою первую сборку” кнопку `Создать сборку` пока не нажимать;
  - команду `npx eas-cli@latest build --platform all --auto-submit` пока не запускать, она нужна позже для публикации в магазины;
- добавить базовую структуру `src`;
- настроить переменную API URL:
  - для телефона в той же Wi-Fi/LAN сети использовать IP компьютера, например `EXPO_PUBLIC_API_BASE_URL=http://<IP-компьютера>:3000`;
  - для Expo web на компьютере использовать `EXPO_PUBLIC_WEB_API_BASE_URL=http://localhost:3000`;
  - не использовать `localhost` на телефоне, потому что там `localhost` означает сам телефон, а не компьютер;
- для Expo web dev добавить CORS на Next API через `proxy.ts`;
- подготовить команды запуска Android/iOS.

Результат: мобильное приложение запускается локально.

Если Expo Go на телефоне все равно показывает ошибку несовместимости:

- проверить, что `npx expo config --json` показывает `sdkVersion: "54.0.0"`;
- полностью закрыть Expo Go на телефоне и открыть заново;
- очистить старый проект/историю в Expo Go, если приложение предлагает старую сессию;
- остановить Metro и запустить заново: `npx expo start --host lan --clear`;
- если при входе появляется `Network request failed`, проверить `mobile/.env.local` и открыть на телефоне в браузере `http://<IP-компьютера>:3000/api/auth`;
- на Android при необходимости установить совместимый Expo Go с `https://expo.dev/go`;
- на iPhone, если App Store версия Expo Go не подходит, использовать development build или временно понижать проект до SDK, который поддерживает установленный Expo Go.

## Критерии готовности мобильной версии

Мобильная версия считается готовой, когда пользователь может:

- зарегистрироваться;
- войти;
- восстановить доступ;
- изменить данные аккаунта;
- добавить контакт;
- создать запись;
- найти запись по контакту или номеру телефона;
- отредактировать запись;
- удалить запись;
- восстановить запись в течение 7 дней;
- выйти из аккаунта.

И при этом приложение остается инструментом учета информации о переводах, а не сервисом денежных переводов.
