# Безопасность и авторизация HunaSuna

## Цель

Помогать делать HunaSuna безопасным рабочим инструментом, где каждый пользователь видит только свои данные и не может получить доступ к чужому аккаунту.

## Основные правила

- Пароли нельзя хранить обычным текстом.
- Секретные ответы нельзя хранить обычным текстом.
- Пользователь не должен видеть свой или чужой пароль.
- Пользователь может менять только свой пароль и данные аккаунта.
- Пользователь видит только свои контакты, записи, историю и удаленные записи.
- Все проверки доступа должны быть на backend.
- UI может скрывать кнопки, но безопасность должна проверяться сервером.
- Для web используется httpOnly cookie.
- Для mobile используется bearer session token через `Authorization: Bearer <token>`.
- Session token в базе хранится только в хешированном виде.

## Регистрация и вход

Пользователь указывает:

- логин;
- пароль;
- секретный вопрос;
- секретный ответ;
- мобильный номер, если хочет;
- email, если хочет.

Логин уникален без учета регистра. После 5 неправильных попыток входа нужно блокировать попытки на 30 минут.

## Восстановление пароля

Восстановление пароля в первой версии работает только через секретный вопрос и ответ.

SMS-коды, email-коды и временные коды восстановления не используются.

После 5 неправильных секретных ответов восстановление блокируется на 30 минут.

## Удаление аккаунта

Удаление собственного аккаунта входит в первую web/mobile версию только как функция приватности и требование App Store.

Правила:

- пользователь может удалить только текущий аккаунт, в котором он вошел;
- клиент не передает `userId` удаляемого аккаунта;
- backend берет пользователя только из текущей web cookie или mobile bearer token;
- для подтверждения пользователь должен увидеть свой секретный вопрос и ввести секретный ответ;
- удаление аккаунта не добавляет платежи, балансы, кошельки, карты, комиссии или реальные денежные переводы.

## Логи

Нужно логировать:

- вход;
- неправильные попытки входа;
- восстановление пароля;
- изменение пароля;
- изменение email;
- изменение мобильного номера;
- создание, редактирование, удаление и восстановление записи;
- удаление аккаунта.

Логи не должны хранить пароль, секретный ответ, session token или лишние персональные данные в открытом виде.

## Проверка качества

Перед завершением security-задачи проверять:

- нет ли доступа к чужим данным;
- нет ли раскрытия пароля, секретного ответа или token;
- API возвращает `401` для анонимных защищенных запросов;
- ошибки пользователю понятны и не содержат stack trace;
- правила одинаково работают для web и `Mobile-App/`.
