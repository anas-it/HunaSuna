# База данных HunaSuna

## Цель

Помогать проектировать базу данных HunaSuna так, чтобы записи, контакты, удаление, восстановление, архивы и аккаунты работали понятно и без путаницы.

## Основные правила

- Все пользовательские данные должны быть связаны с `user_id`.
- Один пользователь не должен видеть данные другого пользователя.
- Запись должна хранить снимок данных отправителя и получателя на момент создания.
- Изменение или удаление контакта не должно менять старые записи.
- Удаленная запись сначала попадает в раздел “Удаленные” на 7 дней.
- Пока запись удалена, ее нельзя редактировать.
- После 7 дней запись исчезает из пользовательского интерфейса окончательно, но остается в техническом архиве без пользовательского доступа.
- Пользователь может удалить только свой текущий аккаунт после ответа на секретный вопрос.
- Удаление аккаунта удаляет пользовательские контакты, записи, удаленные записи, архивные записи и сессии из основной пользовательской базы.
- Сумма и курс сохраняются так, как их указал пользователь, без специальных ограничений формата в первой версии.

## Главные сущности

- `User`;
- `UserSession`;
- `LoginAttempt`;
- `Contact`;
- `Record`;
- `ArchivedRecord`;
- `SecurityLog`.

## Снимок контакта в записи

Для отправителя:

- `sender_contact_id`;
- `sender_first_name_snapshot`;
- `sender_last_name_snapshot`;
- `sender_phone_snapshot`.

Для получателя:

- `receiver_contact_id`;
- `receiver_first_name_snapshot`;
- `receiver_last_name_snapshot`;
- `receiver_phone_snapshot`.

Если пользователь выбрал контакт, сохранять id контакта и снимок данных. Если пользователь ввел данные вручную, id контакта пустой, а имя, фамилия и номер сохраняются как снимок.

## Поиск

Поиск должен работать только по:

- контакту;
- номеру телефона.

Поиск по дате в первой версии не делаем. Поиск должен работать только внутри данных текущего пользователя.

## Проверка качества

При изменении модели данных проверять:

- хватает ли полей для пользовательского сценария;
- не теряется ли история после изменения контакта;
- не смешиваются ли данные разных пользователей;
- не видны ли архивные записи обычному пользователю;
- может ли `Mobile-App/` использовать те же API и ту же базу;
- понятны ли правила удаления и восстановления.
