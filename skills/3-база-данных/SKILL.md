# База данных HunaSuna

## Цель

Помогать проектировать базу данных HunaSuna так, чтобы записи, контакты, удаление, восстановление и архивы работали понятно и без путаницы.

## Основные правила

- Все пользовательские данные должны быть связаны с `user_id`.
- Один пользователь не должен видеть данные другого пользователя.
- Запись должна хранить снимок данных отправителя и получателя на момент создания.
- Изменение или удаление контакта не должно менять старые записи.
- Удаленная запись сначала попадает в раздел “Удаленные” на 7 дней.
- После 7 дней запись исчезает из пользовательского интерфейса окончательно, но остается в техническом архиве базы данных без пользовательского доступа.
- Архивные данные остаются в техническом архиве базы данных без пользовательского доступа.
- Доступ к архиву администрации в первой версии только технический.
- Удаление аккаунта пользователя в первой версии не реализуется.
- Сумма и курс сохраняются так, как их указал пользователь, без специальных ограничений формата.

## Главные сущности

- Пользователь.
- Контакт.
- Запись.
- Сессия пользователя.
- Попытка входа.
- Валюта.
- Курс.
- Удаленная запись.
- Архивная запись.
- Логи безопасности.

## Снимок контакта в записи

Для отправителя:

- `sender_contact_id`
- `sender_first_name_snapshot`
- `sender_last_name_snapshot`
- `sender_phone_snapshot`

Для получателя:

- `receiver_contact_id`
- `receiver_first_name_snapshot`
- `receiver_last_name_snapshot`
- `receiver_phone_snapshot`

Если пользователь выбрал контакт, сохранять id контакта и снимок данных.

Если пользователь ввел данные вручную, id контакта пустой, а имя, фамилия и номер сохраняются как снимок.

Номер телефона при ручном вводе необязателен.

Сумма и курс должны сохраняться в записи в том виде, в котором пользователь их указал.

## Поиск

Поиск должен работать только по:

- контакту;
- номеру телефона.

Поиск по дате в первой версии не делаем.

Если номер телефона не указан, поиск по номеру такую запись не найдет.

Поиск должен работать только внутри данных текущего пользователя.

## Удаление и архив

При удалении запись получает состояние удаленной и дату удаления.

В течение 7 дней пользователь может восстановить запись.

Пока запись удалена, ее нельзя редактировать.

После 7 дней запись не должна отображаться в интерфейсе, поиске, истории, контактах и разделе “Удаленные”.

Архивная запись доступна только администрации и остается в техническом архиве базы данных.

В первой версии доступ к архиву только технический.

## Проверка качества

При изменении модели данных проверять:

- хватает ли полей для пользовательского сценария;
- не теряется ли история после удаления контакта;
- не смешиваются ли данные разных пользователей;
- можно ли потом сделать мобильное приложение на той же базе;
- понятны ли правила удаления и восстановления.
