# Безопасность и авторизация HunaSuna

## Цель

Помогать делать HunaSuna безопасным рабочим инструментом, где каждый пользователь видит только свои данные и не может получить доступ к чужому аккаунту.

## Основные правила

- Пароли нельзя хранить обычным текстом.
- Пользователь не должен видеть свой или чужой пароль.
- Пользователь может менять только свой пароль.
- Пользователь видит только свои контакты, записи, историю и удаленные записи.
- Все проверки доступа должны быть на backend.
- Интерфейс может скрывать кнопки, но безопасность должна проверяться сервером.

## Регистрация

Пользователь указывает:

- логин;
- пароль;
- секретный вопрос;
- секретный ответ;
- мобильный номер с кодом страны, если пользователь хочет указать его сразу;
- email, если хочет.

Минимальная длина пароля - 4 символа.

Мобильный номер можно хранить в аккаунте, но SMS-подтверждение в первой версии не используется.

## Вход и защита от перебора

Если пользователь вводит неправильный пароль 5 раз, вход блокируется на 30 минут.

Ограничение должно учитывать IP и логин или мобильный номер, чтобы защиту нельзя было легко обойти сменой IP.

Пользователь не должен получать подсказки, существует ли чужой аккаунт.

## Восстановление пароля

Восстановление пароля в первой версии работает только через секретный вопрос и ответ.

Секретный ответ нельзя хранить обычным текстом. Нужно хранить только защищенный хеш.

После 5 неправильных секретных ответов восстановление блокируется на 30 минут.

SMS-коды, email-коды и временные коды восстановления не используются.

Пользователь может восстановить только свой аккаунт.

Для удобства в сценарии восстановления можно показывать понятную ошибку, если логин не найден. На обычном входе такую подсказку не показывать: сообщение должно оставаться общим.

## Удаленные записи

Удаленная запись хранится в разделе “Удаленные” 7 дней.

Пока запись находится в разделе “Удаленные”, ее нельзя редактировать.

Пользователь может восстановить только свои удаленные записи.

Архивные записи доступны только администрации и остаются в техническом архиве базы данных. В первой версии доступ к архиву только технический.

## Логи

Нужно логировать:

- вход;
- неправильные попытки входа;
- восстановление пароля;
- изменение пароля;
- изменение email;
- изменение мобильного номера;
- удаление и восстановление записи.

Логи не должны хранить пароль в открытом виде.
